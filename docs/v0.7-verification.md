## Graph Nodes / Edges / Routes

启动 compile 一次，使用真实 StateGraph、NodeAction、Channel Schema 和两次 addConditionalEdges；每请求独立 initial state / executionId，再 invoke。

```text
START → validateInput
  RUNNING_ONLY   → fetchRunningData → analyze → validateOutput → END
  KNOWLEDGE_ONLY → retrieveKnowledge → analyze → validateOutput → END
  COMBINED       → fetchRunningData → retrieveKnowledge → analyze → validateOutput → END
```

固定边有四条：START→validateInput、retrieveKnowledge→analyze、analyze→validateOutput、validateOutput→END。两个条件分支分别发生在 validateInput 和 fetchRunningData；由 mode 决定，没有 LLM Router 或并行分支。

State：executionId、question、mode、startDate、endDate、runningSummary、knowledgeEvidence、analysis、deadlineNanos 使用覆盖 Channel；executedNodes 使用 Channels.appender。Snapshot 的默认内存序列化克隆不启用 Checkpoint Persistence。

## Automated Tests

实际执行：`./gradlew test`、`./gradlew build`；两者成功。XML 汇总：**128 tests / 0 failures / 0 errors / 2 skipped**。两个跳过项是显式可选的真实数据解析与 live model 手工 Tool Calling 实验，常规测试不需要这些依赖。

| 覆盖 | 实际断言 |
| --- | --- |
| RUNNING_ONLY | 顺序 validateInput/fetchRunningData/analyze/validateOutput；search never called |
| KNOWLEDGE_ONLY | 顺序 validateInput/retrieveKnowledge/analyze/validateOutput；running never called |
| COMBINED | 五节点顺序准确，无跳步 |
| Input | 空白、超长、missing mode、无效 enum/日期、缺日期、倒序、超过366天、恰好366天 |
| Running failure | RAG/LLM 不执行；安全 dependency failure |
| RAG failure | disabled/index/查询故障、零召回及空正文均 fail fast，无模型常识兜底 |
| Model failure | 异常、空内容或缺少必需 evidence 是受控失败 |
| HTTP | 三模式 public payload、400/502/503/504、无 State/Prompt/Chunk/Tool Result 字段 |
| Timeout | 50ms Controller deadline，及慢能力返回后不启动后续节点 |
| Cancellation | 即使依赖吞掉 interrupt，取消后也不调用 RAG/LLM |
| Concurrent invoke | 同一 compiled graph 的 question、evidence、executionId、节点列表不串请求 |
| Context | 三模式区块投影；只有两条消息；无 Tools、Memory、内部路径或向量 metadata |
| Local Gateway | 现有 RunningDataService + synthetic fixture 的真实确定性汇总 |
| MCP Gateway | 官方 callback + stub McpSyncClient；只有已过滤 running/getRunningSummary、空 meta、两次请求不重新发现 |
| MCP malformed result | isError、传输故障、error JSON、null、无效 JSON、缺字段、错日期、负数、错数值类型拒绝 |
| Provider switch | local/MCP Gateway 条件装配；MCP 模式无本地 RunningDataService/RunningTools |
| Internal RAG | 完整正文（非200字 preview）、现有 TopK/threshold、仅一次查询 |
| Privacy | 本地假网关空 choices 不得使 OpenAiChatModel 记录 synthetic 敏感 Prompt |

## Real Manual Verification

实际使用本机已安装的 **Ollama bge-m3 + qwen3:8b**。Running 全部为临时 synthetic fixture，未读取真实个人活动。知识检索加载原有四书索引：829 chunks / 1024 dimensions / 4 sources，RAG_REINDEX=false；checksum 与 manifest 一致，无重建或自动下载模型。

独立 JVM：Local Host、MCP Host、Running MCP Server，均只绑定 loopback。Host 显式使用本地 OpenAI-compatible `/v1` 网关，不启用 Weather。

| 路径 | HTTP / 耗时 | 实际 executedNodes | 证据 |
| --- | --- | --- | --- |
| Local RUNNING_ONLY | 200 / 27.13s | validateInput → fetchRunningData → analyze → validateOutput | 本地合成数据；日志没有 retrieveKnowledge |
| Local KNOWLEDGE_ONLY | 200 / 54.99s | validateInput → retrieveKnowledge → analyze → validateOutput | 真实四书索引检索；没有 fetchRunningData |
| Local COMBINED | 200 / 34.72s | validateInput → fetchRunningData → retrieveKnowledge → analyze → validateOutput | 本地合成数据 + 真实知识检索 |
| MCP COMBINED | 200 / 5.31s | validateInput → fetchRunningData → retrieveKnowledge → analyze → validateOutput | Host 本地数据路径故意不可用，Running Server 读取 synthetic fixture；Server 同期记录 getRunningSummary SUCCESS |

以上前两项使用 TopK=5；成功的两个 COMBINED 使用验收进程覆盖 `RAG_TOP_K=2`、`spring.ai.openai.chat.max-tokens=384`，并请求简短回答。最终 MCP COMBINED 另设 `spring.ai.openai.chat.reasoning-effort=none`；已用独立本机 synthetic 请求验证该 Qwen/Ollama 参数返回非空最终内容、无 reasoning_content。该参数见 [Ollama 官方兼容说明](https://github.com/ollama/ollama/blob/main/docs/api/openai-compatibility.mdx)，属于本地模型验收配置，不写入应用默认值。

验收期间 WORKFLOW_TIMEOUT=180s；产品默认仍为60s、TopK=5、threshold=0.5，未改变。两个成功 COMBINED 的实际时长均低于60s，但这不证明任意问题都满足默认预算。最终模型输出非空，没有 think 标签、机器路径或原始 Summary 字段。

真实失败与限制：

- 缺少 COMBINED 日期：400 WORKFLOW_INVALID_REQUEST，日志止于 validateInput。
- 停止本次启动的 Running MCP Server 后再次 COMBINED：0.06s 返回503 WORKFLOW_DEPENDENCY_UNAVAILABLE，日志只有 validateInput 成功、fetchRunningData 失败，没有进入 RAG 或模型；不存在 Host 本地数据回退。
- 初次验收配置缺少网关 `/v1`：返回安全502；纠正仅本地启动参数后 RUNNING_ONLY 成功，没有修改产品 API。
- 默认60s 下两个含 RAG 请求召回5块后未在 deadline 内完成生成，返回504 WORKFLOW_TIMEOUT。
- 将应用期限增大仍不足以保证生成成功：未限制生成长度的 TopK=5 COMBINED 模型调用约60s后失败，返回502。缩短 Context/生成上限后 Local COMBINED 成功。没有把失败记录写成成功验收。
- MCP 的一次受限 token 验收返回空分析，ValidateOutput 正确拒绝并返回502；明确设定本地 Qwen reasoning-effort=none 后相同路径成功。没有返回 HTTP 200 + 空内容。
- Timeout/cancel 只能阻止后续节点，不能保证已经发出的底层 HTTP 立即终止。本次成功也不代表本机模型在默认预算下稳定满足所有问题。
