# RunAgent v0.7 Training Workflow Implementation Plan

**Goal:** 实现附件指定的无状态 Training Analysis Workflow，程序控制执行路径，模型只解释已收集证据。

**Architecture:** LangGraph4j Core 1.8.27，启动时编译一次 StateGraph。五个节点使用局部 State 更新；两个 Conditional Edge 只读显式 mode。Running Gateway 按现有 provider 选择 local/MCP；RAG 复用现有检索；独立 ChatClient 无 Tools、Memory 或 QA Advisor。

**Tech Stack:** Java 21 / Gradle 9.7.1 / Boot 4.1.1 / Spring AI 2.0.1 / WebFlux / LangGraph4j Core 1.8.27。

**Spec:** 用户本轮提供的 RunAgent v0.7 完整需求附件；本计划只补充实现细节，不改变该规格。

## Global Constraints

- 保留 v0.1–v0.6 API、MCP 白名单、noOp metadata、provider 隔离和 RAG 配置。
- 只新增 Core；不使用 Checkpoint/Saver、Retry、Weather Workflow、LLM Router、Multi-Agent。
- 日期 inclusive，最多 366 天；从 RunningTools 提取唯一日期范围校验器。
- HTTP 只返回 executionId、mode、executedNodes、content。日志不输出 State、Prompt、问题、数据或正文。
- 默认 deadline 60s，阻塞调用移出 event loop；取消为 best effort。每个节点边界检查 deadline，避免超时后再进入后续节点。
- 默认 ObjectStreamStateSerializer 会为节点快照做内存克隆，内部证据及 RunningSummary 需可序列化；不配置持久化。
- 本任务只修改 run-agent；不 push，不自动提交，不变更私有书籍、索引、数据或本地配置。

## Design Decisions

- 需求已明确选择 Core + 五节点 + 两条件边；不增加框架选型或改造现有 Agent。
- McpCatalog 在启动发现后另存通过过滤的 connection/tool callback，供确定性调用；不套用 AgentExecutionTrace。
- MCP 结果必须为完整、类型正确、日期一致且非负的 RunningSummary；错误 JSON、缺字段、异常类型均安全拒绝。
- KnowledgeSearchService.retrieveDocuments(queryId, query) 和既有 search/advisorStore 共用 retrieve；Workflow 为检索单独生成 queryId。
- 分析上下文只投影安全汇总字段和来源标题/正文；使用 Message 对象避免用户正文被当作模板处理。

## Review Focus

1. MCP 返回错误对象、残缺或不匹配日期的 Summary 时，不能进入模型。
2. KNOWLEDGE_ONLY 无日期有效；提供不完整或倒序日期时安全拒绝。
3. 同一个 compiled graph 的并发请求不串 State 或 executedNodes。
4. RAG 禁用、索引故障、零召回都 fail fast；没有模型常识兜底。
5. 超时/取消后即使底层调用晚完成，也不能启动下一个节点；日志不能泄漏库内部 State。
