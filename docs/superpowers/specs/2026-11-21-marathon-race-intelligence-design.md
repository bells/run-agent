# RunAgent 赛事日历与官方成绩

## 目标

让 Watson 在现有跑步问答里查未来三个月的重点赛事、某届官方领奖台成绩，以及比赛距离今天还有多久。重庆半马贯通三种用法：查 2026 届赛程，查 2025 届成绩，在一次问答里结合赛程、书籍训练原则和可用的天气预报。

首版收录国内重点全马和半马，以及精选国际重点赛事。用大满贯、世界田联标牌或有出处的国内重点赛事标签支持「热门赛事」查询。网站聊天可以按选手姓名查询最近两年已核验的全马或半马领奖台条目，按赛事日期倒序展示赛事、年份、名次、时间及覆盖范围。采用官方榜单姓名及明确维护的译名。出现多个可能的运动员时给候选。此查询只读本地数据。选手热度榜、生涯档案、跨会话参赛计划、提醒和独立前端页面留待后续评估。

## 方案选择

| 方案 | 代价和收益 |
| --- | --- |
| RunAgent 内部赛事模块 | 沿用 Java 21、Spring AI、WebFlux 和 JSON 文件存储。网站证据链和主 Agent 复用一次实现，沿用现有服务和访问控制。 |
| 独立赛事 MCP | 便于多个客户端复用，并可独立部署采集。需要新增服务运行、工具发现白名单、缓存卷和部署验收。 |

首版选内部模块。赛历由 Python 命令产出，Java 进程读取快照并独占成绩缓存写入。个人活动 JSON、单跑复盘卷和书籍向量索引继续由各自的模块管理。

## 数据契约

Java 用 `record`、枚举、`LocalDate`、`YearMonth`、`Instant` 和显式业务校验定义契约。Python 同步脚本在发布前验证同一版本结构。JSON 使用稳定字段名，文件带 `schema_version`。两端以相同的合成快照夹具检验序列化兼容。

### 赛历快照

- 赛事系列有稳定 `series_id`、正式名称、别名和可核验的分类标签。届次有稳定 `event_id`、`series_id`、届次年份、日期、赛事时区、城市、省级行政区（可缺省）、国家或地区、项目列表、各项目开跑时间（可缺省）、报名截止日期（可缺省）、认证级别（可缺省）、赛程状态和来源。年份代表赛事届次，日期代表实际赛程。跨年改期沿用原届次标识。
- 赛程状态区分计划、已确认、延期、取消和已完赛。日期已过可以确定倒计时结束。完赛状态需要官方战报、成绩页或其他明确的官方赛后证据。赛历记录也可收录用于结果查询的少量历史届次。
- 至少保留来源 URL、来源机构和查验时间。来源不同且日期冲突时采用最新的官方公告，无法判定时保留上一条已核验记录并报告冲突。计划日期和正式日期在响应里可区分。赛事和认证各自以来源的明确措辞为准。
- 显式维护中英文名称和简称，包括广马、上马、北马、厦马、重庆半马。先按归一化名称和别名匹配，再用限定的名称匹配找候选。多个合理候选需要用户选择。重庆半马与重庆马拉松各有系列标识。同一赛事系列的全马与半马用项目字段区分。

### 成绩缓存

- 以 `event_id + distance` 唯一标识成绩文件，包含 `series_id`、赛事日期、届次年份、项目、榜单、赛会亮点和 `updated_at`。查询通过 `series_id` 关联赛事名称。有多个官方榜单时，每个已核验分榜保留自己的来源 URL 和查验时间。已验证的历史成绩同时为相应项目提供完赛证据，Java 将其合并到成绩查询的届次视图。
- 排名条目含组别 `Men | Women`、分榜 `Overall | Domestic`、官方名次、选手姓名、可缺省的国籍、完赛时间、可缺省的赛道纪录标记。缺失分榜或字段表示未发布或未核验。官方中国籍分榜需要明确排名证据；总榜里的中国籍选手同时可作为原总榜条目展示。纪录只在官方有明确依据时标注。亮点采用已核验事实的简短摘要。
- 区分半马和全马的榜单，限定每个组别和分榜的请求范围为前三名，保留官方名次和并列。按官方排名所采用的计时列取值，规范化为 `HH:MM:SS`，用时须为正且分钟和秒合法。核验各字段确实对应同一条排名记录。非结构化正文需要能明确把姓名、组别、名次和用时关联起来。官方仅公布冠军时可以返回一条。用时格式通过仍需证据核验。
- 成绩采用每届每项目一个有界 JSON 文件，路径只由已验证的内部键派生。写入同目录临时文件并原子替换。相同键的在线回填单飞，失败时保留最近可读的有效条目。运行中支持重读已发布的文件与重启后复用。错误缓存和短期退避留在进程内，避免把失败写成正式排名。

## 采集与查询

### 同步未来三个月的赛历

`scripts/sync_marathon_events.py` 提供独立 CLI，可接系统调度。脚本读取可信来源配置和上一份有效快照，拉取本地日期起三个月内的赛事。首版解析至少一个公开国内赛历的列表和赛事条目，按配置的系列范围收录。地区政府、主办方或认证机构公告优先，公开赛历可补充计划状态。国际精选首版通过有出处的配置条目维护。提供 Python fixture 离线验证、dry-run 和调度示例。

同步按稳定届次键合并，保留历史别名和仍用于成绩查询的届次。请求设置超时、响应大小和并发上限。来源临时失败时保留其最近有效条目和来源时间，输出警告。解析为空或候选快照校验失败时，整个文件保持上一版本。一次同步使用独占写锁和同目录原子替换，Java 仅安装通过验证的新快照。

内置带来源的起始快照，首批包含南京马拉松（11 月 22 日）、千岛湖马拉松（11 月 29 日）、厦门海沧半马（12 月 6 日）、广州马拉松（12 月 20 日）、重庆半马（12 月 27 日）及计划中的三亚马拉松（12 月 27 日）。起始成绩覆盖 2025 重庆半马与 2026 柏林马拉松。投放前逐条复核官方来源及可用字段。运行中按日期计算窗口，快照过期或覆盖不全时返回数据更新时间和覆盖范围。

### 查赛历

`query_upcoming_marathons(city?, month?, distance?, limit=10)` 支持城市或省份、`YYYY-MM` 月份和项目过滤。空月份查从今天开始的三个月，指定月份同该窗口取交集。有效范围内的赛事按日期和稳定键升序，默认最多 10 条，最多 30 条。结果带来源、日期状态、快照覆盖和更新时间。延期无新日期、取消和过去的日期从未来列表排除。可按固定标签查重点赛事。

用可注入的 `Clock` 和赛事本地时区计算 `days_until_race` 及 `days_until_registration_deadline`。当天为 0，已知截止日期过去时返回负数并展示为已过截止，截止日期未知时留空。报名已满等业务状态仅在来源明确时说明。没有匹配和数据不可用分别处理。

### 查成绩和按需回填

`get_marathon_podium_results(race_name, year?, category=All, distance?)` 先解析系列和项目，再定位届次。赛事只设一个项目或名字已明确半马时自动选该项目。否则全马为缺省项目，存在实际歧义时给出候选。组别支持 `All | Men | Women`，返回所选组别可核验的总榜和中国籍榜。

1. 显式指定未来届次时说明尚未产生结果。省略年份时找该系列及项目最近一届已确认完赛的赛事。若已知有更新的赛程且日期已过、完成状态未核验，说明可确认的届次和更新届次的状态。最新确认完赛的届次缺官方成绩时提示待发布，可以附上有来源的更早一届并明确年份。
2. 优先读取本地种子及已验证缓存。已有请求组别的可核验条目时直接返回该组别的部分或完整结果。请求组别完全缺失属于未命中。访客和旧版 Agent 入口仅返回已有证据和查询状态。已认证的站主可以通过现有版本化聊天入口查证日期已过的候选届次；已收录系列缺少某个显式指定的历史届次时，也可以按系列、年份、项目查证。未知系列需要用户消歧或由运维收录。已核验的官方历史成绩通过成绩文件补足完赛届次视图，供之后的省略年份查询复用。
3. 首版采用一个显式配置、默认关闭的搜索适配器，初选 Tavily。搜索词由规范赛事名、届次、项目和成绩关键词构造，按来源补充必要中英文变体。只访问配置中与赛事或官方认证机构对应的 HTTPS 来源及允许的重定向，采用有界请求和响应。搜索标题和摘要仅用于选择候选来源。搜不到、站点拒绝访问或内容不足均返回证据缺口。
4. 有官方结构化表时优先解析。使用模型时走独立、无 Tools、无 Memory 的 Spring AI 结构化输出调用。输入限于已解析的赛事标识及官方页面的必要片段。把页面正文当作证据。模型输出提供条目及对应证据行或段落，Java 核对赛事、届次、项目和具体成绩字段，丢弃无证据条目。证据不足以确认赛事身份时整次回填失败。
5. 首次发布成绩需要至少一条核验通过的排名。站主可用明确的「刷新」请求重新查证已命中的届次。新增部分榜单时保留仍可核验的已有分榜。新的官方来源明确更正或撤回时，更新或标记受影响条目失效。全部条目被官方撤回时留存撤回依据，响应说明当前没有有效成绩。刷新失败保留原缓存。日期、候选、空结果、等待发布、依赖不可用和只读未命中以结构化状态表达。重复未命中用短期冷却保护搜索和模型配额。

## 入口、权限与运维

- 按入口选用能力，在 `/api/agent` 显式注册两个 Spring AI ToolCallback，沿用 Tool 调用次数、执行超时和 trace。通过 `PromptCatalog` 管理的 System Prompt 指导模型在赛历和成绩事实问题上查证，在结果未知时保留缺口。Local 和 MCP 模式均可读赛事模块。旧路由按部署现有配置决定是否暴露。
- `/api/v1/chat` 从赛事问题解析出有界查询，直接调用共享赛事服务。服务端保留类型化事实和来源，通过原有正文呈现给当前网站。独立 JSON 赛事字段可在前后端同时升级时加入。沿用现有请求、响应字段、鉴权、站主与访客额度。首版覆盖「最近/下个月/指定月份有什么比赛」「指定赛事什么时候开跑、还有几天、何时截止报名」「某届或上一届谁是冠军或前三」「某选手近期有哪些已核验的领奖台」等常见中文问法，识别已收录的中英文赛事名。遇到不能确定的赛事引用时给出候选或请用户补充。普通训练和天气问题继续使用现有流程。
- 服务器决定回填权限，模型参数和用户文本只描述查询。站主可以在一次提问中提供参赛信息，外部搜索只接收公开赛事标识。查比赛时段的天气用官方地点与开跑时间，由 Weather MCP 判断预报是否覆盖。未确定开跑时间时保留缺口或提示用户补充。用户另问某地、某时段的训练天气时按训练地点与时段查询。输入参赛日期与官方赛历冲突时提示核对。
- 数字、日期、来源等赛事事实由 Java 格式化。网站上能确定查询参数的纯赛事问题直接返回结构化事实及聊天正文，缓存命中无需模型调用。复合问题按已有链路生成训练建议，赛事事实和来源由服务端附在正文。现有网页可从聊天正文看到这一结果。
- 赛事功能和在线回填各自有配置开关。启用赛历可直接使用内置种子，无需新增密钥。生产使用独立的只读赛历挂载和可写成绩卷，支持回滚镜像后重新读回兼容版本。搜索密钥仅从服务端环境变量加载。
- 搜索、官方页面获取和抽取共享小于入口总超时的 deadline。访问限制与取消信号在依赖调用前及发布前检查。触发回填走有界并发与独立次数上限，依赖错误回落到已有证据或明确状态。记录低基数状态、耗时、缓存命中、依赖失败和验证拒绝，日志仅保留排查所需的非敏感元数据。
- 生产首版提供可按需执行和调度的赛历同步 CLI。后续如需计划补齐成绩，由服务端使用同一回填服务和站主预设清单，继续由单一进程写入成绩缓存。

## 验收

| 场景 | 预期 |
| --- | --- |
| 固定为 2026 年 11 月 21 日，查询 12 月重庆半马 | 匹配 12 月 27 日的重庆半程马拉松，按北京时间计算 36 天。验证城市、省份、项目和月份过滤，区分同城全马，正确展示未知或已过报名截止。 |
| 查询重庆半马上届成绩及 2026 届成绩 | 省略年份命中 2025 届男女前三。指定 2026 届提示尚未开赛。已有官方战报缺少国籍、分榜或纪录时保留缺口。 |
| 查询 2026 柏林马拉松女子组 | 展示对应项目和组别、官方前三及官方来源。 |
| 站主成绩缓存未命中，及回填服务层并发 | 替身搜索、官方页和结构化抽取返回证据。相同届次及项目只运行一次回填。缺失历史届次核验后进入届次视图。重启后能读回，下次查询的搜索与抽取调用计数为零。并发聊天请求保留原有 429 行为。 |
| 缓存未命中且访问者未认证 | 正常返回未收录，搜索与抽取调用计数为零。错误令牌遵守既有 401。 |
| 模型给出了合法时间却无对应证据，或页面身份冲突 | 不能发布这些条目，已有缓存仍可读。覆盖搜索或抽取超时、页面不可用、提供部分结果和缓存写失败。 |
| 同步脚本二次运行和失败运行 | 输出键稳定，变更可更新，失败保留上一快照。Java 可读 Python 生成的快照。 |
| Agent 与聊天回归 | 本地 Agent 实际注册并执行两工具，版本化聊天可处理具体赛事问题及用户给出参赛日期的复合问答。通用问答、RAG、Weather MCP 和个人统计通过相关回归。 |

常规测试和 Gradle 构建使用合成数据或替身。受控 smoke 验证真实同步来源、重庆半马和柏林官方成绩，以及一次真实官方结果的未命中回填和随后的缓存读取。未配置搜索密钥时，记录真实回填尚未验证。网站可用以部署后同源入口验收为准。
