# RunAgent 线上天气、四书知识与公开体验

## 目标

面试官从简历打开 Watson Running，在现有线上站点直接体验在线四书检索、Weather MCP 实时查询、基于 Watson 真实跑步记录的 Running MCP 统计，以及真实活动的 AI 复盘。访客无需登录或输入令牌。四书检索在 Mac 离线时可用。沿用三个版本化 API 路径和现有前端入口，以可选字段扩展 Java 与 TypeScript 契约。

## 入口与证据

| 现有接口 | 输入扩展 | 证据与输出 |
| --- | --- | --- |
| `POST /api/v1/chat` | 保留 `message`，可选 `context.city`、`context.runningAt` | 四书 RAG 为训练问题提供依据。有城市的跑前或户外训练问题再查询 Weather MCP。当前条件或选择时段的预报随回答附上，书籍命中返回来源。 |
| `POST /api/v1/training/stats` | 保留现有查询类型和字段，可选 `adviceContext`，包含训练目标及可选城市、计划开跑时间 | 访客查询已公开活动的区间统计。主动请求建议时附上书籍训练原则与计划时段的天气，和统计事实一起展示。统计作为独立结构化字段返回，建议的模型输入限于获准的知识和天气证据。 |
| `POST /api/v1/runs/{runId}/review` | 继续支持空请求体，可选 `adviceContext` | 访客可为公开体验列表中的真实活动生成复盘，根据活动摘要和 Java 配速计算给出训练建议。公开报告使用该活动的固定证据。下次出跑的天气按访客给的城市和时段生成一次性建议，避免将访客位置写入公开报告。 |
| `GET /api/v1/runs/{runId}/review` | 现有路径参数 | 回读已保存的复盘、配速事实及知识依据。老报告可以缺省新增字段。 |

知识和天气使用独立的结构化结果。知识结果包含证据状态、书名和可用的章节或页码。天气结果包含证据状态、城市、时区、有效时段、获取时间和实际拿到的指标。模型生成正文引用这些证据，服务端从检索和工具结果生成来源元数据。缺省、未命中或超时等情况按能力分别返回状态，有证据时继续完成回答。

城市由用户填写或从匹配候选中选择。前端可在本次打开页面期间复用已确认的城市，用户可以随时修改。用户明确询问其他城市时，以问题指定的地点为准。天气查询只使用城市检索及其返回的经纬度和所选时间范围。用户提到「现在」时用当地当前时段，其他日期和时间按地点时区解析。存在歧义或超出预报范围时，请用户明确地点或时间。Weather MCP 请求保持现有三项工具白名单和参数边界。

## 实现方式

- 在服务层复用 `KnowledgeSearchService` 和已经过滤的 Weather MCP callbacks。聊天在需要时收集两类证据，并在请求预算内一次生成回答。旧的仅含 `message` 的请求仍然有效。将检索命中和天气工具输出显式投影为有长度限制的证据输入。
- 训练统计优先完成确定性计算。RunAgent 根据访问权限选择 Running MCP 的数据视图，访客只查询 Watson 已发布的真实活动。可选建议走独立的依赖时间预算，避免外部服务超时阻断统计。
- 复盘 POST 继续复用原来的任务单飞、请求状态与原子持久化。主体报告用配速趋势构造检索主题，传给模型的活动数据沿用已授权范围。公开报告使用独立存储命名空间，以活动 ID 复用。GET 只读与访问权限匹配的报告。属于某次访客请求的天气建议单独返回，存档的训练复盘仅含该活动的固定事实和知识依据。
- 保留现有 API 的总超时作为首轮验收基线。为检索、天气与生成分别分配时间，停止耗尽预算的取证，由剩余证据生成。记录各段耗时、依赖状态和失败原因。依赖输入、原始结果、书摘和用户位置留在各自的数据边界。

## 同一线上部署的公开访问

首页展示可直接操作的问答、真实训练统计和公开活动复盘入口。RunAgent 在同三个 API 内区分访客和站主。请求未携带令牌时进入公开权限范围，携带有效个人令牌时使用现有私有权限，携带无效令牌时返回 401。权限由服务端决定。

- **问答。** 访客可查跑步知识和当地天气。书库查询与生成设置字符和消耗上限。公开答案以归纳和书名、章节等来源信息呈现。索引和正文片段由服务端持有。
- **训练统计。** 公开视图基于与网站发布记录同源的真实活动。公开响应投影为活动数、距离、时长、平均配速和已公开口径内的 PB。Running MCP 在聚合前按视图限定活动范围。视图和查询权限由 RunAgent 服务端传递与验证。
- **复盘。** 首版从已发布的真实活动中指定少量分段数据完整的记录。公开生成和回读使用同一活动白名单，查询报告时先按权限选择命名空间。公开报告只展示对应活动的距离、移动时长、配速派生值及训练建议。
- **请求预算。** 为匿名访问单独配置并发、频率和每日模型调用上限，超限有明确提示。复用基于活动 ID 已生成的公开报告。运行日志保留请求 ID、耗时与状态。

## 在线书库与生成模型

香港侧提供常驻的检索和 Embedding 服务。原始 EPUB 留在 Mac，生产挂载只读索引和 manifest。索引文件包含正文片段，按私有资料保存。部署前校验模型及端点指纹、checksum 和检索结果。迁移时若 Embedding 端点变化导致指纹不兼容，使用目标配置在受控环境重建。RunAgent 当前容器限制为 768 MiB，需测量索引加载及 Embedding 服务常驻后的内存与延迟，再决定是否同机。

首版使用现有 DeepSeek 生成答案，每次只发送少量实际召回的片段及必要问题上下文。公开响应提供归纳、来源书名及可用的章节信息。自管生成模型是独立选项，例如在自己的服务器用 Ollama 或 vLLM 运行 Qwen，RunAgent 调用该实例生成答案。Embedding 负责把问题向量化以找到书摘，生成模型负责根据书摘组织答案，两者可以分开部署。

## 验收

1. Mac 离线时，用手机流量和桌面无痕窗口打开简历 URL。在页面上直接提问「丹尼尔斯的 T 配速有什么用」，可以看到来自对应书籍的答案和书名。询问库外问题时，回答明确说明证据不足。
2. 同一问答入口输入「我在上海，今晚七点出门跑间歇，有什么需要调整」，结果显示实时预报对应的当地时段和适用的书籍来源。切换城市与时段后，工具查询和答案依据随之变化。
3. 统计结果与网站对应时段已公开的真实活动核对一致。选择跑步计划时显示可用的专业依据。天气服务断开时，训练统计和独立知识证据仍然可用。
4. 从公开列表选择真实活动生成复盘，核实分段配速、所用来源及建议。刷新或重启服务后通过原 GET 回读同一份公开报告。重复 POST 复用存档正文。个人令牌可回读历史私有报告。
5. 未发布活动 ID、私人报告和越权统计请求均被服务端拒绝，无效令牌返回 401。公开调用达到独立额度时给出清晰反馈，站主仍可正常使用。
6. 在线验收记录端到端耗时、首次调用耗时、索引就绪、MCP 工具发现、降级行为、公开数据视图和访问权限边界。
