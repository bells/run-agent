# 单次跑步 AI 复盘实施计划

> 按三个可以独立验证的工作包执行。行为变更先写回归测试并观察失败，再实现与复验。

**目标** 从 Classic 的单次跑步入口生成有证据的私有速评，并跨刷新和重启回看。

**架构** Watson Running 发布经过投影的证据文件，RunAgent 验证来源、计算配速并调用结构化模型。私有控制器提供按活动 ID 的读取和生成，持久挂载保存报告。

**技术栈** Node 24、React、TypeScript、Java 21、Spring WebFlux、Spring AI、Docker Compose。

**规格** [单次跑步 AI 复盘](../specs/2026-11-19-single-run-review-design.md)

## 1. 发布证据

- [x] 在 Watson Running 的构建入口生成 `run-review-evidence/{runId}.json`，仅取既有站点快照和日期无关的分段数值。共用前端运行资格判断。验证 ID 不匹配、缺分段、尾段、累计值校验和误差阈值。
- [x] 保证未知证据资源返回 404，Vercel 转发数字 ID 的私有复盘路由，并验证两种基路径构建。

## 2. RunAgent 证据与生成

- [x] 建立类型化证据记录，从配置的固定 HTTPS 站点读取，限制时间与响应，区分 404、格式错和来源不可用。
- [x] Java 计算前后程及切点估算，校验 Spring AI 的结构化证据引用。模型输入只携带派生数值。校验完整分段、空分段、半程跨段、非法引用和基础简报。
- [x] 私有 GET/POST 使用现有令牌，按活动去重和单并发，区分失败、重试和停用。私有 JSON 原子写入，验证重启读取。明确部署默认关闭与受控挂载。

## 3. Classic 入口与验证

- [x] 更新最近一次跑步、手机卡片和桌面表格，详情页支持锚点直达、令牌共享、查询、显式生成和看报告。切换记录取消旧请求并清空旧结果。
- [x] 使用固定的合成四公里样例验证跨仓字段和 HTTP 状态。回归桌面、手机、过期令牌、404、202、错误与已有报告的流程。
- [x] 运行 Java 全量测试和构建、TypeScript、前端 lint、构建和浏览器回归。

## 本地验收记录

- RunAgent 离线全量构建成功。407 项测试中 405 项通过，2 项按现有配置跳过。发布打包、回滚、快照脚本测试和 Compose 持久卷配置检查通过。
- Watson Running 通过 TypeScript、格式、ESLint 和 12 项证据及 HTTP 契约测试。Chromium 桌面与手机完成新复盘和现有私有助手回归。Classic 根路径、Classic 子路径和 Dashboard 构建通过。
- 本机浏览器经 Vite 请求实际 RunAgent，使用进程内合成证据和替身模型。桌面生成分段报告，Java 重启后手机读回报告且调用次数不变，只有基础数据的记录生成简版。每条新记录触发一次替身模型。
- 生产代理与实际模型生成另行验收，向模型传输真实指标需相应授权。
