# 单次跑步 AI 复盘

## 使用流程

Watson 在 Classic 首页或历史列表选中一条已有跑步记录，在原详情页生成或查看私有报告。报告回答本次表现、一个可改进点和下一次怎么跑。有足够分段时优先解释前后程节奏变化。评分、跨周期分析和分享留给后续产品决策。

| 位置 | 交互 |
| --- | --- |
| 首页最近一次跑步 | 「查看详情」旁显示「AI 跑后复盘」。直达链接定位详情页的复盘卡片。 |
| 桌面表格和手机历史卡片 | 用一个「详情 · AI 复盘」链接进入原详情页，保留原有返回位置和选中记录的地图联动。 |
| 单次详情页 | 在运动概览与每公里配速之间显示卡片。只有基础数据的跑步在基础概览后渲染同一张卡片。 |
| 卡片状态 | 未授权时提示输入访问令牌，授权后查询报告。未生成时显示「生成报告」，已有报告显示「查看报告」。生成中提示等待，失败时允许手动重试。 |

可复盘的记录是进入发布摘要且具有正里程、正移动时长的跑步。列表标注表示可用，已有报告状态在详情页显示。浏览和查看报告无需模型。直达卡片支持键盘焦点和移动触摸。SPA 会话共享现有访问令牌，刷新后重新输入。

## 摘要来源

已同意由 Watson Running 在发布构建中生成每条跑步的精简摘要。浏览器提供路径中的 `runId`，RunAgent 从配置指定的固定 HTTPS 站点读取 `/run-review-evidence/{runId}.json`。构建产物与页面使用同一批活动数据并支持站点基路径。摘要只投影已发布的活动数值和分段。活动名称、地点、精确时间、设备、路线、生理数据和原始采样留在现有数据层。

由浏览器提交指标可以减少构建工作，但后端无法独立确认数值对应所选记录。现有 MCP 跑步快照使用另一套内部 ID，提供基础统计，缺少分段。采用发布摘要可以核对记录身份和分段来源，并覆盖只有基础数据的旧跑步。

| 字段 | 约束 |
| --- | --- |
| `schemaVersion` | 固定为 `1`。 |
| `runId` | 正安全整数，必须和请求路径一致。 |
| `distanceMeters` | 正的有限米数。 |
| `movingSeconds` | 正的整数秒。 |
| `splits` | 按跑步顺序排列的区间，每段为 `distanceMeters`、`movingSeconds` 和 `partial`。分段缺失或无法核对时为空数组。 |

优先使用身份匹配且通过校验的详情中的距离和移动时长。无有效详情时取活动列表中的基础数值。只有全程连续且分段合计与全程数据可核对时才写入分段。RunAgent 限制单份摘要为 32 KiB、最多 200 个分段，读取期限 3 秒。只访问固定来源，禁止重定向，验证 MIME、字段与记录 ID。发布路由让不存在的摘要返回真正的 404。若上游返回 HTML、格式无效或超时，按来源故障处理。

发布端以公开详情的 `distance_m` 和 `moving_seconds` 为米和秒，核对每段累计距离与累计移动时长是否和分段累加一致。分段数值必须有限且为正，累计值严格递增。最后一段可以是 `partial: true`，完整段的距离须在 995 至 1005 米。分段合计与全程数据允许最多 10 米和 2 秒的舍入差。发布端与 Java 用同一组边界样例核对该规则。不能通过的活动仍生成基础摘要。

## 计算与报告

Java 计算全程平均配速、前半与后半的平均配速，以及后半相对前半的每公里秒数变化。全程配速用移动秒数除以公里数。前后半以通过校验的分段总距离的 50% 切分，切点落在分段内时按距离比例估算时长，并标注「估算」。末尾不足一公里的分段计入全程。前后程分析要求至少两个完整公里段且分段覆盖全程。条件不足时用简版呈现全程事实与一条可执行建议。展示配速四舍五入到秒，快慢判断按未舍入值比较，每公里差距在 5 秒以内显示为接近。

模型输入仅包含已计算的白名单证据。首版拟采用距离、移动时长、全程配速、可用时的前半配速、后半配速和差值。路径 ID 用于服务端关联报告。独立提示词让 Spring AI 返回结构化结果，包含 1 至 2 个 `observationEvidenceIds`、一个 `improvementEvidenceId` 和一条 `nextRun` 建议。Java 根据入选证据渲染本次表现、真实数值与节奏判断，模型负责选重点与给出建议。生成结果通过字段、长度、引用和分析模式校验后才保存。`nextRun` 只表达下一次做什么及观察什么。简版可以提出下次留意的一项指标，无需从本次基础数据推导问题。

开发和 CI 通过独立测试配置注入本地合成摘要与替身模型。生产配置不提供切换到测试数据或绕过授权开关的路径。真实活动字段的模型外发授权在生产启用前单独确认，真实记录的生成默认关闭。有权用户仍可读取已保存报告，未生成的记录显示「生成暂未开放」。

## 私有 API 与保存

- `GET /api/v1/runs/{runId}/review` 读取报告，不访问摘要源站。已有报告返回 200，正在生成返回 202，无报告返回 404 `REVIEW_NOT_FOUND`。
- `POST /api/v1/runs/{runId}/review` 无请求体。生成成功返回 201，已生成返回 200，进行中返回 202。未知记录返回 404 `RUN_NOT_FOUND`，摘要源故障返回 503 `EVIDENCE_UNAVAILABLE`。其他跑步的生成已占满并发时返回 429 `REVIEW_BUSY`，停用生成时返回 503 `REVIEW_GENERATION_DISABLED`。模型超时或无效输出返回 503 `REVIEW_GENERATION_FAILED`。
- 两条接口均沿用现有 Bearer 令牌，先检查鉴权，再读取状态或数据。响应使用 `Cache-Control: no-store` 和请求 ID。生成使用独立并发上限和超时，前端在进行中只查询状态。
- 单实例按活动 ID 去重，模型生成并发默认上限为一。首次 POST 等待生成结果，服务端总期限默认 25 秒并短于客户端和代理期限。客户端离开只取消等待。生成失败释放占用，并在有限的进程状态中保留 10 分钟供 GET 和复盘卡片显示重试。重新生成会替换失败状态。成功报告经同目录临时文件原子提交。
- 以独立私有持久挂载保存每条记录的一份报告。报告包含生成时间、版本、证据算法版本、输入摘要指纹以及模型和提示词版本。进程重启后和支持该报告格式的新版发布后可以回看。回退到早期二进制时保留文件，恢复支持该格式的版本后重新开放查看。首版采用原报告留存策略。
- 日志和指标只记录固定状态、阶段与耗时。Vercel 与 Caddy 只代理对应私有路径，UI 和 API 可分别关闭。

### 响应契约

200 或 201 的成功报告具有 `status: "READY"`、`requestId` 和 `report`。报告含以下字段。

| 字段 | 类型和含义 |
| --- | --- |
| `schemaVersion`、`runId`、`generatedAt` | 格式版本、活动 ID 和 ISO 8601 生成时间。 |
| `mode` | `SUMMARY` 或 `SPLIT_COMPARISON`。 |
| `facts` | `distanceMeters`、`movingSeconds`、`averagePaceSecondsPerKm`，分段模式另含 `firstHalfPaceSecondsPerKm`、`secondHalfPaceSecondsPerKm`、`paceDeltaSecondsPerKm` 和 `estimated`。差值为后半减前半。 |
| `observations`、`improvement`、`nextRun` | 1 至 2 条由 Java 生成的表现文字、基于同一证据的改进或观察重点，以及经过校验的下一次训练建议。 |

202 返回 `status: "GENERATING"` 和 `requestId`。失败状态的 GET 返回 200，包含 `status: "FAILED"`、`requestId` 和固定的 `code`。失败状态以及 `REVIEW_NOT_FOUND` 响应附上 `generationEnabled` 供界面展示当前是否可生成。错误响应使用现有 `requestId`、`code`、`message` 结构，包含未授权 401 和无效 ID 400。`SPLIT_COMPARISON` 中前后程事实由服务端呈现，`SUMMARY` 省略这些字段。

## 验收

1. 首页直达复盘卡片，桌面和手机历史列表都能发现入口。带分段与只有基础数据的记录均可复盘。原有详情、地图定位和返回位置仍可用。
2. 合成 4 公里记录前两公里各 300 秒，后两公里各 330 秒。报告显示前半 5:00/km、后半 5:30/km、每公里慢 30 秒。另测切点跨分段、短尾段、节奏接近与缺分段。
3. 模型替身和日志断言验证白名单。错误 ID、重定向、HTML、坏摘要和未知证据编号均不能写入报告。
4. 匿名查询和生成返回 401。已授权重复请求只触发一次模型调用，报告落盘后重启可读取。重复请求收到 202 后能读到终态，生成失败后可重试。关闭生成的情况下仍能查看历史报告。
5. 合成数据端到端覆盖桌面、手机、未生成、生成中、已有报告与失败状态。摘要与公开详情来自同次构建。真实数据路线获授权后单独生产验收。
