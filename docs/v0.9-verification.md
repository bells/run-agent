## Graph structure and Supervisor

```text
START → supervisor
          ├→ runningAnalyst ─┐
          ├→ knowledgeCoach ┤→ supervisor → ...
          └→ weatherAdvisor ┘
          └→ FINISH / guard → synthesize → validateOutput → END
```

Coordinator 构造时 compile 一次。实际路径测试验证三次 Supervisor handoff，以及 maxDelegations=2 时跳过第三次 Router 调用。1.8.27 的 distinct Appender 会移除重复 supervisor，因此 delegationPath 明确使用 appenderWithDuplicate。

Supervisor 独立无工具 ChatClient，Spring AI BeanOutputConverter 根据 record/enum 生成 Schema 并映射响应。Java 验证 null/未知 nextAgent、空/超长 task、重复 Specialist、不可用能力与预算。FINISH 允许 null task，但至少已有一个成功报告。没有自动重试。

## State and control

State 的16个 override 字段为 executionId、question、startDate、endDate、location、availableAgents、nextAgent、delegatedTask、delegationCount、runningReport、knowledgeReport、weatherReport、runningStatus、knowledgeStatus、weatherStatus、finalAnswer。completedAgents 使用 distinct Appender，delegationPath 使用允许重复的 Appender。

每请求 UUID、State 和 ExecutionControl 独立。deadline/cancel 保存在本地 RunnableConfig metadata，工具所需的 trace/hints 保存在 Host ToolContext。没有会话 Memory、数据库、Saver 或 Checkpoint。

## Specialists and capability isolation

| Role | 实际能力与上下文 |
| --- | --- |
| Supervisor | 原问题、hints、availability/status、bounded reports，零工具 |
| Running Analyst | 原问题、自己的 task、日期，三项 Running tools，无 RAG/Weather/Memory |
| Knowledge Coach | 原问题、自己的 task、显式检索的安全来源/正文，零工具 |
| Weather Advisor | 原问题、自己的 task、location，三项 Weather tools，无 Running/RAG/Memory |

测试实际检查模型请求的 tool definitions 和初始消息条数。Running local 复用真实 RunningTools/RunningDataService；mcp 只取 McpCatalog 已过滤的 running 快照，不 fallback local。Knowledge 使用真实 retrieveDocuments 与自创合成知识。Weather 使用合成 callbacks 和官方 MCP adapter 协议边界测试。

显式日期在 Summary/Recent 参数边界覆盖，location 覆盖位置搜索 name。天气查询坐标必须来自成功 geocoder 返回的候选，候选仅保存在本次 trace 中。没有 GPS 推断。仅地点搜索或空天气 envelope 不能形成天气报告。合法空 RecentRuns 仍能表示无活动。

## Delegation limits and failure isolation

默认最多三次委派，每个 Specialist 最多尝试一次，失败同样 completed 且消耗预算。达到预算或无可选能力后直接结束路由。只要存在 SUCCESS，就可汇总其他证据并说明缺失。

测试覆盖 Weather、Knowledge、Running 分别不可用，以及三者全部失败、无任何可用 capability、Supervisor 故障、Synthesis 故障、空答复/空报告、duplicate decision 和 concurrent requests。全部证据失败返回 MULTI_AGENT_INSUFFICIENT_EVIDENCE，Synthesis 不运行。

## Bounds, cancellation and privacy

报告默认2500字符，配置范围500–5000。Prompt 限制后再由 Java 截断，避免切断 surrogate pair，节点写 State 前再次强制。Knowledge 输入证据最多12000字符，来源标题最多200字符。任务默认2000字符，最大配置4000。

默认全局180s，配置最多一小时。阻塞 Graph/LLM/MCP 在 boundedElastic，取消或 deadline 后不启动下一 Agent。测试使用吞掉 interrupt 的慢 Specialist 验证这一点，并检查 late return 后 root/stage timeout 观测停止、scope 清理、最终 delegation summary 只记录一次。底层 Provider HTTP 仍属于 best effort cancellation。

MCP 实际 CallToolRequest 检查 _meta 为空、只有 schema 参数，并确认请求不会重新 initialize/tools/list。本地 MethodToolCallback 因 Spring AI 2.0.1 要求非空 ToolContext，只接收固定 requestType marker，使用独立 Multi-Agent trace 计数。

## Independent review

## Regression and current limitations

既有 Chat、UTF-8 Streaming、Intent、Agent Loop、Memory、RAG、Running/Weather MCP、Workflow、Evaluation、Observability 自动回归通过。真实供应商 Streaming、真实四书 RAG、真实 Running/Weather MCP 与外部观测平台没有因自动测试而被视为已验收。

固定三个顺序 Specialist，无并行、persistent state、checkpoint、retry、long-term memory、human approval、peer-to-peer handoff、动态 Agent 或生产认证。模型仍可能误路由、错误压缩证据、遗漏限制或生成不准确建议；Java 执行边界不等于自然语言事实核验。

Weather geocoder 需要可解析的坐标字段，forecast/AQ 必须原样复用候选坐标。未知结果格式会安全降低可用性。报告超长会截断，可能损失后半部分细节。这些实现选择需要结合真实 Server/模型持续验收。

最终 git diff --check 及所有新增文本空白检查通过；新增文件无真实凭据、GPS/Polyline、书籍、索引、Prompt dump、报告内容、私有评估或观测数据。现有 .run-agent 与 build 产物保持忽略。
