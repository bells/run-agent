## Privacy 回归与配置发现

两个新增隐私测试先复现失败，再修复通过：

1. Spring AI 2.0.1 默认 VectorStore convention 会导出 `db.vector.query.content`，关闭 query-response 日志无效。安全 convention 去掉向量操作高基数属性后，实际检索的敏感哨兵不再进入导出属性。
2. Provider 500响应正文会进入 OTel exception event。使用公开 Boot ObservationHandlerGroup 让 AI error sanitizer 先于 tracing group执行后，内存 exporter 的 attributes/events不含哨兵。普通handler的 @Order本身不能覆盖Boot grouping顺序；按Context类型匹配，避免选handler时name尚未赋值。

业务与AI exporter错误使用固定、无cause/stack的异常；应用正常的领域错误传播保持。代价是Trace不保留供应商原始异常类型与堆栈。

Boot4.1.1实际metadata确认OpenTelemetry starter还默认启用OTLP Metrics；明确关闭默认Trace/OTLP Metrics/Logs，避免自动向collector发起连接。敏感AI采集false属性与回环绑定通过实际配置加载验证。

随机回环Management端口的真实HTTP测试确认：health/info/metrics/prometheus可访问，health无components详情，env/configprops/beans/heapdump/threaddump/loggers/shutdown均404。测试发现原全局ExceptionHandler会把不存在静态资源404改成500，增加精确NoResourceFoundException映射后修复。真实Prometheus输出包含自定义agent histogram bucket与tool-call summary，无executionId或密钥。
